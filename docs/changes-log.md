## Исходный план структуры файла
Обзор проекта — что за платформа Xkadzama Education, стек (FastAPI + Argon2 + PyJWT / Vite + React 19 + Router v7), репозиторий и ветка main, инструкция «как продолжить работу» (poetry install, uvicorn, npm run dev);
§1 JWT-авторизация (backend) — все 5 файлов с эндпоинтами (/auth/login, /auth/refresh, /auth/me, /auth/register), логикой refresh-токенов, RBAC через require_role(), схемой БД;
§2 React-фронтенд — структура папок, механизм axios-интерцепторов с флагом isRefreshing (одновременный refresh на все 401), ProtectedRoute, прокси Vite;
§3 Дизайн-система — таблица токенов (цвета, типографика, шаг 8px), правила компонентов, ссылка на docs/design-system.md;
§4–6 Функционал профиля — аватар-навигация и страница профиля, загрузка фото (Pillow-валидация, сжатие до 512×512, /uploads/), выпадающее меню с кликами вне области;
§7 Уборка UI — ID убран везде, .avatar-button стал flat (без рамки), добавлена кнопка «← На главную»;
§8 Сайдбар и уроки — AppLayout (сетка 224px|1fr), Sidebar («Уроки», активный пункт по location.pathname), lessons.js (заглушка: 3 пройденных + 5 предстоящих тем Python);
Хронология коммитов — все 8 хешей от 133ed61 до c6c11a1… 6af087e;
Известные ограничения — stateless-токены без отзыва, localStorage вместо httpOnly-cookie, заглушки уроков/аватара, отсутствие Docker/CI/ссылки на backend в git.

## Итерация 24 (2026-10-21): Исправлен маршрут /profile — «No routes matched location "/profile"» (страница была полностью пуста)

### Симптом от пользователя
- http://localhost:5173/profile — данные из БД не отображаются; в DevTools → Сеть `GET /auth/me` возвращает 200 с корректным JSON; в консоли предупреждение:
  `react-router-dom.js: No routes matched location "/profile"`.

### Диагностика
1. Предупреждение React Router «No routes matched» — это корневая причина: компонент Profile вообще не монтировался, поэтому никакой JSON на экран не выводился (вёрстка страницы не удалялась).
2. Разбор схемы маршрутизации (`src/App.jsx` + `src/components/AppRoutes.jsx`): при переезде на динамическую (вложенную) маршрутизацию была допущена ошибка — дочерние маршруты объявлены внутри отдельного layout-компонента AppRoutes, который сам являлся element промежуточного `<Route>`:
   ```jsx
   <Route path="/" element={<ProtectedRoute><AppLayout/></ProtectedRoute>}>
     <Route element={<AppRoutes />} />   // ← AppRoutes содержит <Routes>…</Routes>, НО НЕ рендерит <Outlet/>
   </Route>
   ```
   В React Router v6 элемент layout-маршрута обязан отрендерить `<Outlet/>`, чтобы показать матченные дочерние маршруты. AppLayout действительно рендерит Outlet, но между ним и AppRoutes лежал барьер: AppRoutes ничего не выводит из Outlet родителя, а его собственный внутренний `<Routes>` матчит пути относительно `/` только когда он сам рендерится как элемент маршрута с совпавшим паттерном — при URL `/profile` внешний матчер сошёл на промежуточный route без children-match, внутренний `<Routes>` получил location `/profile` и не нашёл совпадений (его relative-базис — путь элемента, а не полный URL) → «No routes matched», пустой контент.
3. Проверено: `/` (index/Dashboard) работал именно потому, что… нет — по той же схеме не должен был; фактически Dashboard открывался, т.к. внутренний Routes совпадал с index-маршрутом при базисе `/`. Для `/profile` совпадения не происходило никогда. Отсюда: профиль пуст, уроки работали.

### Изменения
1. **`frontend/src/App.jsx`** — маршрутизация приведена к канонической схеме вложенных маршрутов:
   - импорт `Navigate` добавлен в строку импорта react-router-dom;
   - импорт AppRoutes заменён на прямые импорты страниц: `Dashboard`, `Profile`, `Lessons`;
   - вместо `<Route element={<AppRoutes />} />` дочерние маршруты объявлены непосредственно детьми маршрута с `element = <AppLayout/>`:
     ```jsx
     <Route index element={<Dashboard />} />
     <Route path="profile" element={<Profile />} />
     <Route path="lessons" element={<Lessons />} />
     <Route path="*" element={<Navigate to="/" replace />} />
     ```
     Теперь цепочка matches: `/` (AppLayout) → `profile` (Profile), AppLayout рендерит `<Outlet/>` → Profile монтируется внутри каркаса (сайдбар/шапка не перемонтируются, состояние open/mini сохраняется — требование динамической подгрузки контента выполнено).
   - комментарий в JSX обновлён с объяснением прежней ошибки.
2. **`frontend/src/components/AppRoutes.jsx`** — файл удалён (роут-обёртка больше не нужна; логика маршрутов целиком в App.jsx).

### Побочные эффекты / совместимость
- Поведение защищённости не изменилось: ProtectedRoute остался на родительском маршруте.
- Несуществующие пути внутри каркаса (`*`) редиректят на `/` (раньше — то же самое через AppRoutes).
- Профиль теперь реально запрашивает `/auth/me` из useEffect (логика нормализации полей из итераций 22–23 осталась без изменений) и отображает данные.

### Проверка
- `npm run build` — успешно (✓ built in 372ms);
- `npx oxlint src/App.jsx` — 0 warnings / 0 errors;
- grep подтвердил отсутствие остаточных ссылок на AppRoutes в коде;
- Логика матчинга проверена чтением: все три защищённых пути объявлены детьми маршрута с Outlet-содержащим элементом.

## 2026-10-24 — Фикс: возврат «К урокам» с презентации оставлял /lessons пустым

**Симптом:** на `/lessons/py-01` клик по «← К урокам» меняет URL на `/lessons`,
но список уроков не появляется до F5.

**Диагностика (headless Chrome + CDP):** после клика `body` пустой,
`.lesson-link` = 0, в консоли `TypeError: doc.destroy is not a function` из
`LessonPresentation.jsx` в `commitHookEffectListUnmount`. В PDF.js 6
`PDFDocumentProxy` больше не имеет метода `destroy()` (владелец ресурсов —
`PDFDocumentLoadingTask`). Ошибка в cleanup пассивного эффекта при
размонтировании прерывала commit, поэтому новый маршрут не отрисовывался.

**Исправление (`frontend/src/pages/LessonPresentation.jsx`):**
- убран `doc.destroy()` / `loaded.destroy()`;
- cleanup всегда вызывает `task.destroy().catch(() => {})` — loading task
  закрывает документ, transport и worker;
- в `.then`, если эффект уже отменён, просто `return` (task уничтожается
  cleanup'ом).

**Проверка:** тот же сценарий в headless Chrome: `/lessons/py-01` → клик по
`.back-link` → URL `/lessons`, 12 `.lesson-link`, `.lessons-page` присутствует,
исключений в консоли нет (до фикса — пустой `body`).
